# Загрузка в Git и размещение

В архиве готовый статический сайт. Основной файл `index.html` должен оказаться в корне репозитория. Загружать ZIP как единственный файл в репозиторий не нужно: сначала распакуйте его.

## 1. Загрузить в GitHub через браузер

1. Создайте новый репозиторий в своём аккаунте GitHub. Название, например, `legal-brief`.
2. Для подключения отдельного хостинга репозиторий может быть приватным. Для GitHub Pages доступность публикации из приватного репозитория зависит от плана аккаунта.
3. Выберите **Add file → Upload files**; в пустом репозитории может отображаться ссылка **uploading an existing file**.
4. Загрузите распакованные файлы в корень репозитория: прежде всего `index.html`, затем остальные файлы пакета. При выборе скрытых файлов включите их отображение в файловом менеджере.
5. Сохраните изменения через **Commit changes** в основную ветку, далее в примерах — `main`.

Проверка: открыв репозиторий, вы видите `index.html` сразу, без перехода во вложенную папку.

Официальная инструкция: [загрузка файлов в репозиторий](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

### Если удобнее через установленный Git

Выполните в папке с распакованными файлами:

```sh
git init -b main
git add index.html README.md DEPLOY.md QUESTIONS.md .gitignore .nojekyll
git commit -m "Add client legal brief"
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git
git push -u origin main
```

Замените `YOUR-ACCOUNT` и `YOUR-REPOSITORY` на свои значения. Для этих команд создайте пустой удалённый репозиторий без первоначального README. В существующий репозиторий не отправляйте изменения принудительно: добавьте файлы в его текущую историю.

## 2. Cloudflare Pages: размещение из GitHub

1. В Cloudflare откройте создание проекта **Pages** и подключение существующего Git-репозитория. Выбирайте Pages, а не проект Worker.
2. Подключите GitHub и выберите нужный репозиторий.
3. Укажите параметры:

| Параметр | Значение |
|---|---|
| Production branch | `main` или фактическая основная ветка |
| Framework preset | `None` |
| Build command | `exit 0` |
| Build output directory | `.` |
| Root directory | корень репозитория; оставить пустым |
| Environment variables | не нужны |

4. Запустите размещение и дождитесь успешного статуса.
5. Откройте выданную HTTPS-ссылку. Последующие сохранённые изменения основной ветки будут публиковаться через интеграцию с Git.

Поле output directory указывает на папку с `index.html`; в этом пакете это корень `.`. Никаких `npm install` и `npm run build` нет.

Официальные инструкции: [Static HTML](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/), [build configuration](https://developers.cloudflare.com/pages/configuration/build-configuration/).

## 3. GitHub Pages: альтернативный способ публикации

1. В репозитории откройте **Settings → Pages**.
2. В разделе **Build and deployment** выберите **Source → Deploy from a branch**.
3. Выберите ветку `main`, папку **/(root)** и нажмите **Save**.
4. Дождитесь завершения публикации и откройте ссылку, показанную GitHub. Не используйте для клиентов ссылку на исходный HTML в интерфейсе репозитория.

Публикация из приватных репозиториев доступна не во всех планах. Для просмотра сайта по ссылке не требуется право редактировать репозиторий.

GitHub ограничивает использование Pages для ведения онлайн-бизнеса и коммерческих SaaS. Перед использованием брифа в рабочем коммерческом процессе проверьте применимость условий; наличие кода в GitHub не обязывает размещать сам сайт на GitHub Pages. Можно хранить код в GitHub, а публиковать на другом статическом хостинге.

Официальные источники: [настройка источника публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [ограничения Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

## 4. Другой статический хостинг

Разместите `index.html` в корневой папке сайта. Если панель спрашивает каталог публикации — укажите папку, содержащую этот файл. Бэкенд и запуск процесса Node.js не нужны. Встроенного контроля доступа в HTML нет: при необходимости настройте его на стороне хостинга.

## 5. Проверка после размещения

Откройте новую ссылку на телефоне и компьютере. Проверьте:

- отображаются семь шагов и поле короткого описания проблемы;
- итоговая проверка содержит введённые ответы;
- TXT скачивается с читаемым русским текстом;
- черновик JSON скачивается и восстанавливается через «Продолжить из файла»;
- документы передаются отдельно, а ответы не отправляются автоматически;
- после изменения `index.html` и публикации открывается обновлённая версия.

Для испытания используйте вымышленные данные. Если меню «Поделиться файлом» не поддерживается браузером, скачайте TXT и прикрепите его к сообщению вручную.

## Обновление вопросов

Вопросы, названия шагов и текст выгрузки находятся внутри `index.html`, в блоке `<script>`. При добавлении или удалении вопроса согласуйте экран формы, `pairsForStep()` для итоговой выгрузки и список полей в `normalizeDraft()`. После обновления проверьте совместимость старых черновиков. Без изменения поведения достаточно править подписи и подсказки.
